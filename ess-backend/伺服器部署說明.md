# ESS 戰情版後端 — 公司伺服器部署說明

> 目的：把資料抓取＋LINE 推播從 GitHub Actions 雲端（免費排程延遲嚴重）
> 改成在公司伺服器本機 24 小時常駐執行，徹底解決延遲問題。
> 前端網頁（戰情版）**不用動**，繼續放 GitHub Pages，因為它是直接讀
> Firestore 雲端資料庫，跟後端在哪裡跑無關、不會延遲。

---

## 架構異動一覽

| 項目 | 之前 | 現在 |
|---|---|---|
| 資料抓取＋LINE 推播 | GitHub Actions（雲端排程，常delay）| **公司伺服器 `app.py` 常駐**（09:00/13:00/16:30 推 LINE，每 `CACHE_MINUTES` 分鐘抓資料）|
| GitHub Actions | 自動排程執行 | **已停用**（只保留手動觸發，當緊急備援）|
| 前端網頁 | GitHub Pages 讀 Firestore | **不變** |
| 資料存放 | Firestore | **不變** |

⚠️ **重要**：伺服器本機和 GitHub Actions **不能同時排程**，否則會重複推播、
提早耗盡 LINE 免費額度（每月 200 則）。這次已經把雲端排程停用，只要
伺服器持續開機執行，就不會重複。

## 第一次部署步驟（在公司伺服器上執行）

### 1. 安裝需求
- **Python 3.11 以上**（[python.org](https://www.python.org/downloads/) 下載安裝，安裝時記得勾選「Add to PATH」）
- **Git**（[git-scm.com](https://git-scm.com/download/win)，方便之後用 `git pull` 更新程式）

### 2. 取得程式碼
在伺服器上開一個資料夾（例如 `C:\ess-backend`），執行：
```bash
git clone https://github.com/mnj711211-glitch/bess-yield-expert.git
cd bess-yield-expert/ess-backend
```

### 3. 安裝套件
```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m playwright install --with-deps chromium
```

### 4. 放入敏感設定檔（⚠️ 這兩個檔案不在 Git 裡，必須手動搬過去）
從**這台電腦**（開發機）複製以下兩個檔案到伺服器同一個 `ess-backend` 資料夾：

| 檔案 | 這台電腦的位置 |
|---|---|
| `.env` | `C:\Users\user\Desktop\claude\ess-backend\.env` |
| `firebase-key.json` | `C:\Users\user\Desktop\claude\ess-backend\firebase-key.json` |

**搬運方式**（挑一種）：
- USB 隨身碟直接複製過去（最簡單、最安全，不經過網路）
- 用公司內部網路磁碟機共用
- 若伺服器與這台電腦不同網段，用加密的方式傳（例如密碼保護的壓縮檔），
  **不要**用 LINE / Email 明碼傳這兩個檔案（裡面有帳密和金鑰）

複製完成後，`ess-backend` 資料夾裡應該要有 `.env` 和 `firebase-key.json`
這兩個檔案，內容不用改，跟開發機一模一樣即可。

### 5. 測試手動啟動一次
```bash
python app.py
```
看到類似下面的訊息代表成功，按 `Ctrl+C` 結束測試：
```
本機排程啟動：每 30 分鐘更新快取；LINE 告警總覽 09:00/13:00/16:30
```

### 6. 設定「開機自動啟動」＋「當機自動重啟」
滑鼠右鍵點 `register_startup_task.bat` → **「以系統管理員身分執行」**，
照畫面指示按 Enter 即可（會問要不要立刻測試啟動一次，可以按 Y）。

完成後：
- 伺服器**開機**（就算沒有人登入）就會自動啟動後端
- `app.py` 若**意外當機**，會在 5 秒後自動重啟（`start_backend.bat` 內建的迴圈）
- 不需要留一個終端機視窗開著，是背景執行的排程工作

## 之後怎麼確認有在正常運作

- **看戰情版網頁**：資料有沒有持續更新（`fetched_at` 時間）
- **看 LINE**：每天 09:00 / 13:00 / 16:30 應該收到通知
- **看 log**：`ess-backend\backend.log`（超過 20MB 會自動輪替成 `backend.log.old`）
- **查排程工作狀態**：
  ```bash
  schtasks /query /tn "ESS-Backend-AutoStart"
  ```

## 常用管理指令
```bash
schtasks /run /tn "ESS-Backend-AutoStart"     REM 手動啟動
schtasks /end /tn "ESS-Backend-AutoStart"     REM 停止
schtasks /delete /tn "ESS-Backend-AutoStart" /f   REM 移除排程
```
若要完全手動停止背景執行中的 `python.exe app.py`，用工作管理員結束該
process，或：
```bash
taskkill /IM python.exe /F
```
⚠️ 這會把該台機器所有 python.exe 都關掉，若伺服器只跑這一個 python
程式就沒問題，否則請改用工作管理員找到正確的 PID 再關。

## 之後怎麼更新程式碼
```bash
cd C:\ess-backend\bess-yield-expert
git pull
schtasks /end /tn "ESS-Backend-AutoStart"
schtasks /run /tn "ESS-Backend-AutoStart"
```

把 `.github/workflows/ess-fetch.yml` 和 `ess-digest.yml` 裡被註解掉的
`schedule:` 區塊取消註解即可還原。但要記得同時把伺服器本機的
`register_startup_task.bat` 那個排程工作刪掉，避免雲端＋本機重複推播。
